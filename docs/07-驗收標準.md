# 07 驗收標準

## 1. 測試資料集（由 JC 提供，不進 repo）
放在 JC 個人 Google Drive「名片夾/驗收測試」資料夾或本機 `testdata/`：

| 組 | 內容 | 數量 |
|---|---|---|
| S 單張 | 一張照片一張名片，涵蓋：純中文、純英文、中英同面、雙面（中/英各一面）、直式名片、深色底、反光/略歪斜 | ≥ 20 張照片 |
| M 多張 | 一張照片 3–10 張名片平放桌面，含相鄰無間隙、不同大小、部分歪斜 | ≥ 5 張照片（合計 ≥ 25 張名片） |
| N 無名片 | 不含名片的照片（文件、桌面） | 2 張 |

標準答案 `truth.json`：每張名片的關鍵欄位正確值與大致框。由 Claude 依照片先擬初稿，JC 逐筆確認後定稿（JC 確認的才算標準答案）。

## 2. 量化指標與門檻
以下指標以**預設引擎**（驗收後選定者）計算；另一家引擎同樣量測並列在報告中。

| 代號 | 指標 | 計算方式 | 門檻 |
|---|---|---|---|
| A1 | 名片偵測召回率（M 組） | 偵測到的名片 / 實際名片 | ≥ 95% |
| A2 | 名片偵測誤報（M+N 組） | 不存在卻被偵測出的框數 | N 組 0 個；M 組合計 ≤ 1 |
| A3 | 框品質（M 組） | 裁切圖包住整張名片且多餘背景 < 15% 的比例 | ≥ 90%（其餘可手動調整） |
| A4 | 關鍵欄位正確率 | 姓名（中/英）、公司（中/英）、職稱、手機、Email 正規化後完全相符的比例 | S 組 ≥ 97%、M 組 ≥ 93% |
| A5 | 全部欄位正確率 | 所有非空欄位逐欄比對 | ≥ 90% |
| A6 | 繁體保真 | 中文欄位出現簡體字或被翻譯的次數 | 0 |
| A7 | 低信心標示有效性 | 錯誤欄位中有被列入 low_confidence 的比例 | ≥ 50%（參考值，不擋驗收） |
| P1 | 延遲（S 組） | 送出到收到結果 P90 | ≤ 15 秒 |
| P2 | 延遲（M 組） | 同上 | ≤ 30 秒 |
| C1 | 單張名片平均費用 | RecognitionLog | 記錄並回報；目標 ≤ NT$1 |

## 3. 自動評測（`tools/eval/run.mjs`）
- 對每張測試照片以 `provider: "compare"` 呼叫一次，另以 Claude `effort: medium` 再跑一次（共三組結果）。
- 框比對：以 IoU ≥ 0.5 將預測框與標準答案配對，再計 A1–A3。
- 欄位比對：兩邊都先經 `lib_normalize` 再比對；姓名比對忽略空白，Email 忽略大小寫。
- 輸出 `eval-report-<日期>.md`：總表（各指標 × 各引擎設定）、每張名片錯誤明細（期望值 vs 實際值）、費用與延遲統計。
- 報告與測試資料不進公開 repo；存到專案共用資料夾或 Drive。

## 4. 手動驗收（Pixel 8 實機，JC 操作）
| # | 情境 | 通過條件 |
|---|---|---|
| U1 | 從 Chrome 安裝 App，從主畫面開啟 | 全螢幕開啟，無網址列 |
