# 03 資料模型

後端唯一真實來源是一份 Google 試算表「名片夾資料庫」（由 `setup.js` 建立），含以下工作表。第 1 列為欄位代碼（英文，程式用），第 2 列凍結顯示中文標題供 JC 閱讀；資料從第 3 列開始。

## 1. 工作表 `Contacts`（聯絡人）

| 欄位代碼 | 中文標題 | 型別 | 說明 |
|---|---|---|---|
| id | ID | string | `c_` + 時間戳 + 隨機碼，例 `c_20261119_8f3a2k` |
| name_zh | 中文姓名 | string | |
| name_en | 英文姓名 | string | 保留名片原樣大小寫 |
| title_zh | 中文職稱 | string | |
| title_en | 英文職稱 | string | |
| department | 部門 | string | 中英皆可，原樣保留 |
| company_zh | 公司中文全名 | string | |
| company_en | 公司英文全名 | string | |
| company_short | 公司簡稱 | string | **顯示用**；AI 建議（例「台積電」「PrimoBio」），使用者可改 |
| mobile | 手機 | string | 多筆以 ` ; ` 分隔，E.164 格式（`+886912345678`） |
| phone | 市話 | string | 多筆以 ` ; ` 分隔，E.164，分機另存 |
| phone_ext | 分機 | string | |
| fax | 傳真 | string | E.164 |
| email | Email | string | 多筆以 ` ; ` 分隔，小寫 |
| website | 網址 | string | 補上 `https://` |
| address_zh | 中文地址 | string | |
| address_en | 英文地址 | string | |
| line_id | LINE ID | string | |
| linkedin | LinkedIn | string | 完整網址或帳號 |
| other_social | 其他社群 | string | `平台: 帳號` 以 ` ; ` 分隔（WeChat、Facebook、X…） |
| tags | 標籤 | string | 以 `, ` 分隔 |
| event | 場合 | string | 例：BIO Asia 2026 |
| met_date | 取得日期 | date | yyyy-mm-dd |
| notes | 備註 | string | |
| front_image_id | 正面圖 Drive ID | string | 最新一張名片的正面 |
| back_image_id | 背面圖 Drive ID | string | |
| source_photo_id | 原始照片 Drive ID | string | |
| card_history | 歷次名片圖 | string | 舊名片的 front_image_id，以 ` ; ` 分隔 |

| ai_model | 辨識模型 | string | |

| created_at | 建立時間 | datetime | ISO 8601（台北時區 +08:00） |
| updated_at | 更新時間 | datetime | 任何變更都更新；Sheets 手動編輯由 onEdit 觸發器更新 |
| deleted | 已刪除 | boolean | 軟刪除 |

## 2. 工作表 `TitleHistory`（職稱變動歷程）

| 欄位代碼 | 中文標題 | 說明 |
|---|---|---|
| id | ID | `h_...` |
| contact_id | 聯絡人 ID | 對應 Contacts.id |
| company_zh / company_en / company_short | 當時公司 | |
| department | 當時部門 | |
| title_zh / title_en | 當時職稱 | |
| valid_until | 記錄至 | 被新名片取代的日期 |
| first_seen | 首次取得 | 這組職稱最早出現的 met_date |
| card_image_id | 當時名片圖 | |
| recorded_at | 寫入時間 | |

規則：合併到既有聯絡人時，只要 `company_zh`、`company_en`、`department`、`title_zh`、`title_en` 任一（正規化後）不同，就把**舊值**寫一列到 TitleHistory，然後更新 Contacts。

## 3. 工作表 `RecognitionLog`（辨識紀錄）
`ts, provider, model, photo_bytes, cards_detected, latency_ms, input_tokens, output_tokens, est_cost_usd, status, error_code, compare_group_id`

`est_cost_usd` 依 Script Properties 中的單價設定計算（`PRICE_CLAUDE_IN`、`PRICE_CLAUDE_OUT`、`PRICE_GEMINI_IN`、`PRICE_GEMINI_OUT`，單位 USD / 百萬 tokens）。

## 4. 工作表 `Log`
系統事件與錯誤（未授權嘗試、例外堆疊摘要）。不得寫入金鑰或權杖。

## 5. 重複比對規則（`lib_dedupe.js`，前後端共用邏輯）
依序計分，總分 ≥ 60 視為疑似同一人，回傳分數最高的最多 3 位候選：
| 條件 | 分數 |
|---|---|
| 任一 Email 完全相同（小寫） | 100 |
| 任一手機號碼相同（E.164） | 90 |
| 中文姓名相同且公司（任一語言全名或簡稱）相同 | 70 |
| 英文姓名相同（忽略大小寫、空白、標點）且公司相同 | 70 |
| 姓名相同但公司不同 | 40（只在加上其他條件時計入） |

已軟刪除的聯絡人不參與比對。

## 6. Google Drive 結構
```
名片夾/
├─ cards/2026/11/   c_<id>_front_<yyyymmddHHMMss>.jpg、c_<id>_back_...jpg
└─ photos/2026/11/  p_<yyyymmddHHMMss>_<rand>.jpg   # 原始照片
```
資料夾 ID 存在 Script Properties `DRIVE_FOLDER_ID`。

## 7. 手機端 IndexedDB（資料庫名 `bizcard`）
| store | key | 內容 |
|---|---|---|
| contacts | id | Contacts 一列的物件，加上 `_thumb`（快取狀態） |
| photoQueue | localId | 待辨識照片 Blob、建立時間、狀態 `pending/sending/failed` |
| drafts | localId | 已辨識未儲存的確認頁狀態（防止誤關頁面遺失） |
| pendingChanges | seq | 離線時的編輯/刪除 |
| meta | key | `lastSyncAt` 等 |
