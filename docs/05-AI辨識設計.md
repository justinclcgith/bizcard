# 05 AI 辨識設計

## 1. 原則
- 一張照片一次呼叫，模型同時回傳「每張名片的位置」與「結構化欄位」。
- 兩家引擎使用**同一份提示詞與同一份輸出 Schema**，由 `recognize.js` 統一正規化，前端不需知道是哪一家。
- 位置框統一格式 `box_2d: [ymin, xmin, ymax, xmax]`，0–1000 正規化整數（Gemini 原生格式；Claude 依提示詞輸出同格式）。
- 文字原樣保留：繁體不轉簡體、不翻譯、不臆測名片上沒有的資訊（`company_short` 例外，是建議值）。

## 2. 提示詞（`recognize.js` 的 `PROMPT_V1`，存成常數並帶版本號）

```
你是名片辨識系統。圖片中可能有 0 到 20 張名片，可能是正面或背面，可能歪斜或倒置。

請找出圖片中每一張「完整或大部分可見」的名片，依由上到下、由左到右的順序，對每張輸出：
1. box_2d：名片外框 [ymin, xmin, ymax, xmax]，以整張圖片寬高正規化為 0–1000 的整數。框要包住整張名片，寧可略大不要切到。
2. orientation：讓文字轉正需要順時針旋轉的角度："0" / "90" / "180" / "270"。
3. fields：名片上的資訊。規則：
   - 完全照名片上的字抄寫，繁體中文保持繁體，不要翻譯，不要轉成簡體。
   - 名片上同時有中文與英文時分別填入 *_zh 與 *_en；只有一種語言時只填那一種，另一個留空字串。
   - 姓名：name_zh 為中文姓名（不含職稱），name_en 為英文姓名（保留原大小寫）。
   - 電話：所有號碼依名片原樣抄寫到 mobiles / phones / faxes，分機寫在 ext。手機是 09 開頭或標示 Mobile/M/手機 的號碼。
   - company_short：依常見稱呼建議公司簡稱（例如「台灣積體電路製造股份有限公司」→「台積電」，「PrimoBio Inc.」→「PrimoBio」），沒有把握時用英文名稱的主要字詞或中文名稱去掉「股份有限公司」等字尾。
   - 看不清楚或沒有的欄位填空字串，不要猜。
4. low_confidence_fields：你不確定的欄位名稱清單（例如字太小、反光、手寫）。
5. side："front"（有姓名的一面）、"back"（只有公司資訊或另一語言）、"unknown"。

只輸出符合 Schema 的 JSON。圖片中沒有名片時，cards 為空陣列。
```

背面辨識（`side: "back"` 請求）時在提示詞後加一句：「這是某張名片的背面，請照同樣規則輸出，box_2d 可為整張圖。」

## 3. 輸出 JSON Schema（`CARD_SCHEMA_V1`）
所有物件 `additionalProperties: false`，所有屬性皆列入 `required`（缺值用空字串或空陣列）。不使用 min/max 等數值限制（Claude 結構化輸出不支援），範圍檢查在正規化階段做。

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["cards"],
  "properties": {
    "cards": {
      "type": "array",
      "items": {
        "type": "object",
        "additionalProperties": false,
        "required": ["box_2d","orientation","side","fields","low_confidence_fields"],
        "properties": {
          "box_2d": { "type": "array", "items": { "type": "integer" } },
          "orientation": { "type": "string", "enum": ["0","90","180","270"] },
          "side": { "type": "string", "enum": ["front","back","unknown"] },
          "low_confidence_fields": { "type": "array", "items": { "type": "string" } },
          "fields": {
            "type": "object",
            "additionalProperties": false,
            "required": ["name_zh","name_en","title_zh","title_en","department",
              "company_zh","company_en","company_short","mobiles","phones","faxes",
              "emails","website","address_zh","address_en","line_id","linkedin","other_social"],
            "properties": {
              "name_zh": {"type":"string"}, "name_en": {"type":"string"},
              "title_zh": {"type":"string"}, "title_en": {"type":"string"},
              "department": {"type":"string"},
              "company_zh": {"type":"string"}, "company_en": {"type":"string"},
              "company_short": {"type":"string"},
              "mobiles": {"type":"array","items":{"type":"string"}},
              "phones": {"type":"array","items":{
                "type":"object","additionalProperties":false,
                "required":["number","ext"],
                "properties":{"number":{"type":"string"},"ext":{"type":"string"}}}},
              "faxes": {"type":"array","items":{"type":"string"}},
              "emails": {"type":"array","items":{"type":"string"}},
              "website": {"type":"string"},
              "address_zh": {"type":"string"}, "address_en": {"type":"string"},
              "line_id": {"type":"string"}, "linkedin": {"type":"string"},
              "other_social": {"type":"array","items":{"type":"string"}}
            }
          }
        }
      }
    }
  }
}
```

## 4. Claude 呼叫（`ai_claude.js`，用 `UrlFetchApp`，GAS 沒有官方 SDK，故用 REST）
```
POST https://api.anthropic.com/v1/messages
Headers:
  x-api-key: <ANTHROPIC_API_KEY>
  anthropic-version: 2026-10-21
  anthropic-beta: server-side-fallback-2026-07-01
  content-type: application/json
Body:
{
  "model": "<CLAUDE_MODEL，預設 claude-opus-5-5>",
  "max_tokens": 16000,
  "fallbacks": "default",
  "output_config": {
    "effort": "<CLAUDE_EFFORT，預設 low>",
    "format": { "type": "json_schema", "schema": CARD_SCHEMA_V1 }
  },
  "messages": [{ "role": "user", "content": [
    { "type": "image", "source": { "type": "base64", "media_type": "image/jpeg", "data": "<base64>" } },
    { "type": "text", "text": PROMPT_V1 }
  ]}]
}
```
- 回應：先檢查 `stop_reason`：`refusal` → `AI_REFUSED`；`max_tokens` → `AI_ERROR`（輸出被截斷）。正常時取 `content` 中 `type == "text"` 的區塊 `JSON.parse`。
- 用量：`usage.input_tokens`、`usage.output_tokens`；實際回應的 `model` 欄位寫入紀錄（fallback 時可能不同）。
- 不設 `temperature`（此 API 版本已不接受）、不送 `thinking: disabled`（Opus 5.5 會 400）。
- P2 開發時先以 1 張測試圖實際呼叫確認格式；若官方文件與本節不符，以官方文件為準並更新本節。
- effort 調校：驗收時比較 `low` 與 `medium` 的準確度與延遲，選擇達標中較便宜者。

## 5. Gemini 呼叫（`ai_gemini.js`）
```
POST https://generativelanguage.googleapis.com/v1beta/models/<GEMINI_MODEL>:generateContent
Headers: x-goog-api-key: <GEMINI_API_KEY>, content-type: application/json
Body:
{
  "contents": [{ "role": "user", "parts": [
    { "inline_data": { "mime_type": "image/jpeg", "data": "<base64>" } },
    { "text": PROMPT_V1 }
  ]}],
  "generationConfig": {
    "responseMimeType": "application/json",
    "responseJsonSchema": CARD_SCHEMA_V1
  }
}
```
- 預設模型 `gemini-3.6-flash`；P0 時查 Google 官方文件確認當下模型 ID 與 `responseJsonSchema` / `responseSchema` 參數名稱，必要時調整。
- 回應：`candidates[0].content.parts[*].text` 串接後 `JSON.parse`；`finishReason` 非 `STOP` 時視為錯誤（`SAFETY` → `AI_REFUSED`）。
- 用量：`usageMetadata.promptTokenCount`、`candidatesTokenCount`（含 thinking 時加上 `thoughtsTokenCount`）。
- 必須使用**已啟用計費**的 API 金鑰（免費方案資料可能被用於改善產品）。

## 6. 正規化（`lib_normalize.js`，Node 可測）
| 項目 | 規則 |
|---|---|
| box_2d | 長度必須為 4，夾在 0–1000，ymin<ymax、xmin<xmax，否則設為整張圖並加 warning |
| 電話 | 去除空白、`-`、括號；`09xxxxxxxx` → `+8869xxxxxxxx`；`0x-xxxx-xxxx` → `+886x...`；已有 `+` 保留；`#`、`ext.`、`分機` 後的數字移到 ext |
| Email | 去空白、轉小寫、驗證含 `@` 與 `.`，不合格者保留原字串並列入 low_confidence |
| 網址 | 無協定時加 `https://`；`linkedin.com/in/...` 若出現在 website 則移到 linkedin |
| 全形字元 | 英數與 `@`、`.`、`-` 的全形轉半形（中文不動） |
| 空白 | 前後去空白；中文姓名內的空白移除（「王 小 明」→「王小明」） |
| 重複卡片 | 兩框 IoU > 0.7 時視為同一張，保留欄位較多者 |

## 7. 費用估算（寫入 RecognitionLog）
- Script Properties 存單價（USD / 百萬 tokens）。初始值：Claude Opus 5.5 輸入 4、輸出 20；Gemini 依 P0 查到的官方價格填入。
- 每次辨識 `est_cost_usd = in × 單價入 / 1e6 + out × 單價出 / 1e6`。

## 8. 影像前處理（PWA）
- 長邊縮到 2400px（多張名片時解析度很重要；單張可縮到 1600px，由 PWA 依使用者選擇「單張/多張」模式或自動以原圖比例判斷，預設 2400）。
- JPEG 品質 0.85；轉正 EXIF；不做灰階或銳化（交給模型）。
- 裁切：依 `box_2d` 換算像素、各邊外擴 2%，再依 `orientation` 旋轉，輸出長邊 1200px 的 JPEG 存檔。
