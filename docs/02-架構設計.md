# 02 架構設計

## 1. 元件

```
┌──────────── Pixel 8 / Chrome ─────────────┐
│ PWA（GitHub Pages, HTTPS）                 │
│  - 拍照/選圖、縮圖、裁切（Canvas）          │
│  - 確認頁、清單、搜尋、設定                 │
│  - IndexedDB：聯絡人快取、待辨識佇列         │
│  - localStorage：GAS URL、APP_TOKEN、偏好   │
└───────────────┬───────────────────────────┘
                │ HTTPS POST（Content-Type: text/plain，JSON 字串）
                ▼
┌──────── Google Apps Script Web App ───────┐
│ （JC 個人帳號，執行身分：我；存取：任何人） │
│  doPost → 驗證 APP_TOKEN → 依 action 分派   │
│  - recognize：呼叫 Claude / Gemini          │
│  - saveCards / updateContact / list ...     │
│  Script Properties：API 金鑰、APP_TOKEN、   │
│    SHEET_ID、DRIVE_FOLDER_ID、模型名稱       │
└──────┬──────────────┬──────────────┬──────┘
       ▼              ▼              ▼
  Google Sheets   Google Drive   Claude API / Gemini API
  （資料）        （圖檔）       （辨識）
```

## 2. 主要資料流

### 2.1 辨識與儲存
1. 使用者拍照 → PWA 縮圖、轉正 → 產生 `photoLocalId`，原圖暫存 IndexedDB。
2. PWA `POST {action:"recognize", image(base64), provider}` → GAS 呼叫 AI → 正規化 → 回傳 `cards[]`（欄位 + `bbox` + 信心）與用量；GAS 同時寫一筆辨識紀錄。
3. PWA 依 `bbox` 以 Canvas 裁出單張圖（外擴 2% 邊界），顯示確認頁。
4. 使用者修正後按儲存 → PWA 先 `POST {action:"findDuplicates", cards}` 取得疑似重複 → 使用者決定合併或新增。
5. PWA `POST {action:"saveCards", sourcePhoto, cards[ {fields, cropImage, mergeIntoId?} ]}` → GAS 存圖到 Drive、寫 Sheets、必要時寫職稱歷程 → 回傳 `contacts[]`。
6. PWA 更新 IndexedDB 快取，刪除暫存原圖。

### 2.2 同步
- 開 App 或下拉更新 → `POST {action:"list", since}` → 回傳 `updated_at > since` 的聯絡人（含已軟刪除者，以便手機端移除）。
- 圖片以縮圖網址延遲載入：`POST {action:"getImage", fileId, size}` 回傳 base64（GAS 用 `DriveApp.getFileById().getThumbnail()` 或原檔），PWA 以 Cache Storage 快取。

### 2.3 離線
- 無網路時拍的照片存入「待辨識佇列」（IndexedDB），連線恢復（`online` 事件或開啟 App）時提示「有 N 張待辨識」，使用者點擊後依序送出。
- 編輯與刪除在離線時排入「待同步變更」，連線後送出；衝突時以後端 `updated_at` 較新者為準並提示。

## 3. GAS Web App 呼叫注意事項
- 使用 `Content-Type: text/plain;charset=utf-8` 送 JSON 字串，避免 CORS 預檢（GAS 不處理 OPTIONS）。
- GAS 回應會 302 轉址到 `script.googleusercontent.com`，`fetch` 預設 `redirect: "follow"` 即可。
- 所有回應格式：`{ ok: true, data }` 或 `{ ok: false, error: { code, message } }`，HTTP 一律 200（GAS 限制），PWA 以 `ok` 判斷。
- 單次執行上限 6 分鐘；比較模式時兩家 AI 用 `UrlFetchApp.fetchAll` 平行呼叫。
- 部署版本：使用固定的「部署 ID」網址；更新程式碼時建立新版本到同一部署，網址不變。

## 4. 安全設計
- APP_TOKEN：至少 32 字元隨機字串，存在 Script Properties 與手機 localStorage；每個請求放在 JSON body 的 `token` 欄位。比對使用固定時間比較。
- 錯誤權杖回傳 `UNAUTHORIZED`，且 GAS 以 `CacheService` 記錄失敗次數，同一小時超過 20 次則暫停所有請求 1 小時並在 Sheets `Log` 記錄。
- Drive 資料夾與 Sheets 不分享給任何人；圖片透過 GAS 以 base64 取回，不使用公開連結。
- AI 金鑰只在 Script Properties；GAS 的錯誤訊息不得回傳金鑰或完整 AI 回應內容以外的設定值。
- 公開 repo 內不出現 GAS 部署網址（使用者首次開啟時在設定頁輸入，或掃 QR code 匯入設定）。

## 5. 技術選型
| 層 | 選擇 | 備註 |
|---|---|---|
| 前端 | Vite 6+、TypeScript strict、Preact、preact-iso（路由） | 體積小 |
| PWA | vite-plugin-pwa（Workbox），`registerType: "autoUpdate"` | App shell 離線可用 |
| 本機儲存 | `idb` 套件包 IndexedDB | 快取與佇列 |
| 影像 | Canvas API、`createImageBitmap(file, {imageOrientation:"from-image"})` | 轉正、縮圖、裁切 |
| 測試 | Vitest（前端與 GAS 純函式）、Playwright（行動版模擬 E2E，Pixel 7 裝置描述檔） | |
| 後端 | Google Apps Script V8、clasp 管理原始碼 | |
| 部署 | GitHub Actions → GitHub Pages（`vite build`，`base` 設為 `/<repo>/`） | |
